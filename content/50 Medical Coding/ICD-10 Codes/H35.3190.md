# 🧬 ICD-10-CM H35.3190 — Nonexudative AMD, Unspecified Eye, Stage Unspecified

> [!danger] ⚠️⚠️ DOUBLE DOCUMENTATION DEFICIENCY — Critical Alert
> **ICD-10 CM [[H35.3190]]** carries the **lowest specificity of any code in the entire nonexudative AMD family.** Two required clinical elements are simultaneously absent:
>
> | Deficiency | Character | Value | What's Missing |
> |---|---|---|---|
> | **Laterality** | 6th character | `9` = Unspecified eye | Which eye has AMD? Right? Left? Both? |
> | **Stage** | 7th character | `0` = Stage unspecified | Early? Intermediate? Advanced? |
>
> Per ICD-10-CM Official Guidelines **Section I.B.4** (highest specificity) and **Section I.B.13** (**laterality**), both elements are mandatory when the documentation supports them. In any ophthalmology encounter, the treating physician **always** documents which eye is being examined. There is virtually no scenario in retina practice where the eye is genuinely unknown. **[[H35.3190]]** on a retina claim is a compliance signal that something went wrong upstream — either in documentation or in the coding workflow.

> [!warning] Non-Billable Parent Codes — Also Do Not Use
> - ❌ `H35.319` — 6-character header — non-billable; missing stage
> - ❌ `H35.31` — 5-character header — non-billable; missing laterality AND stage
> - ❌ `H35.3` — 4-character header — non-billable; subcategory only

---

## 🔍 Code Description

**ICD-10 CM [[H35.3190]]** classifies **nonexudative (dry) age-related macular degeneration affecting an unspecified eye at an unspecified stage** — meaning the record documents dry AMD but provides no information about which eye is affected or how advanced the disease is. This code exists in the ICD-10-CM tabular as a structural necessity — the code set must account for all possible combinations of laterality and stage — but it is not intended for routine clinical use. 

In practice, **[[H35.3190]]** should be thought of as the **absolute coding floor** for dry AMD — the code you reach only after all other documentation sources have been exhausted, a CDI query has been attempted, and no additional information can be obtained. Even then, it signals a documentation failure that should be corrected prospectively.

> [!note] The H35.319x Family — ALL Are Suboptimal
> Even **[[H35.3191]]** through **[[H35.3194]]** — which correctly specify the stage — are still suboptimal because the **laterality (which eye) remains unspecified**. In any encounter where a physician examines a patient, the eye is always specified.

## 🚨 The Laterality Rule — Why "Unspecified Eye" Is Especially Problematic

> [!danger] ICD-10-CM Section I.B.13 — Laterality Is Mandatory When Documented
> ICD-10-CM Official Coding Guidelines Section I.B.13 states: *"For bilateral sites, the final character of the codes in the ICD-10-CM indicates laterality. An unspecified side should be coded only if laterality is not identified in the medical record."* 
>
> The key phrase: **"only if laterality is not identified in the medical record."** In ophthalmology, this is essentially never the case. Consider:
> - The physician examines right eye, left eye, or both eyes — they always document which eye
> - The OCT report is labeled by eye (**OD/OS/OU**)
> - Fundus photos are labeled by eye
> - Prior visit notes identify the affected eye
> - The patient can be asked which eye has AMD
>
> If a coder assigns **[[H35.3190]]** on an outpatient ophthalmology claim, it means the laterality was not captured despite being available in the record — this is a **coder documentation review failure**, not a physician documentation gap.

### The Three Laterality Options — Pick the Right One

| Situation | Correct Laterality Code |
|---|---|
| AMD documented in **right eye only** | H35.311x — right eye |
| AMD documented in **left eye only** | H35.312x — left eye |
| AMD documented in **both eyes** (bilateral) | H35.313x — bilateral |
| AMD documented in **right eye** at one stage, **left eye** at different stage | Separate right AND left codes |
| Laterality genuinely **unknown** (rare — history only, no exam) | H35.319x — unspecified eye |

> [!tip] "Bilateral" vs. Two Separate Codes — When to Use Each 
> Use the **bilateral code (H35.313x)** when both eyes are at the **same stage** — e.g., both eyes have early dry AMD (H35.3131).
>
> Use **separate right + left codes** when the two eyes are at **different stages** — e.g., right eye intermediate dry ([[H35.3112]]) + left eye advanced subfoveal ([[H35.3124]]). Never use the bilateral code when stages differ between eyes.

## 🔍 When H35.3190 Might Be Defensible — Rare Scenarios

### The Legitimate Use Cases for H35.319x (Any Unspecified-Eye Code)

| Scenario | Defensible? | Notes |
|---|---|---|
| **Emergency department** — patient reports "AMD" in history, no eye exam performed, no prior records | ✅ Yes | Eye genuinely unknown without examination |
| **Primary care H&P** — "history of AMD" documented, no ophthalmic records available, no referral yet | ✅ Yes | Laterality may not be in the PCP record |
| **Inpatient admission** — AMD in problem list, no ophthalmology consult, no ophthalmic records available during coding window | ✅ Yes (with query attempt) | After query, use H35.319x if eye still unknown |
| **Administrative/intake coding** — enrollment form lists "AMD" without further detail | ✅ For administrative purposes | Update when clinical records obtained |
| **Retina practice outpatient visit** — physician examined patient and documented which eye | ❌ NOT defensible | Eye is always specified in ophthalmology exam |
| **Any encounter with an OCT report** | ❌ NOT defensible | OCT report specifies OD/OS/OU |
| **Any encounter where prior notes exist** | ❌ NOT defensible | Prior records establish laterality |

> [!note] H35.3190 vs. H35.3191-H35.3194 — When Stage Is Documented But Eye Is Not
> If a note documents "intermediate dry AMD" without specifying the eye — use **[[H35.3192]]** (unspecified eye, intermediate stage) rather than **[[H35.3190]]**. At minimum, capture the stage that IS documented. **[[H35.3190]]** should only be used when BOTH elements are missing.

## 🛠️ Double CDI Query Template — H35.3190 → Specific Code

> [!success] Combined Laterality + Stage Query — Use When Both Are Missing
> When the record documents only "AMD" or "dry AMD" with no eye or stage specified, send this two-dimensional query:
> 
```
CLINICAL DOCUMENTATION IMPROVEMENT QUERY
Date: _
Patient: _ MRN: _
Encounter Date: _ Provider: _

RE: Dry (Nonexudative) AMD — Laterality AND Stage Clarification Required

The medical record documents age-related macular degeneration
(dry/nonexudative type). Accurate ICD-10-CM coding requires
both the affected eye AND the disease stage.

QUESTION 1 — WHICH EYE IS AFFECTED?
□ Right eye only
□ Left eye only
□ Both eyes (bilateral)
□ Cannot be determined

QUESTION 2 — WHAT IS THE CURRENT STAGE?
(Answer separately for each affected eye)

Right Eye Stage:
□ Early dry (medium drusen, no pigment changes)
□ Intermediate (large drusen or pigment changes)
□ Advanced — geographic atrophy, NOT at foveal center
□ Advanced — geographic atrophy AT foveal center (subfoveal)
□ Stage unspecified / cannot be determined

Left Eye Stage:
□ Early dry (medium drusen, no pigment changes)
□ Intermediate (large drusen or pigment changes)
□ Advanced — geographic atrophy, NOT at foveal center
□ Advanced — geographic atrophy AT foveal center (subfoveal)
□ Stage unspecified / cannot be determined

Physician Signature: _ Date: _

NOTE: Without laterality and stage, only the lowest-specificity
ICD-10-CM code is assignable, which may affect claim processing
and quality metric reporting.
```

## 💊 Coding Scenarios

---

### Scenario 1 — ED Visit, Patient Reports AMD History, No Exam (Emergency Department)

> **Clinical Vignette:** A 78-year-old female presents to the ED with a fall. Her social history and problem list state "AMD — on eye drops." No eye exam performed. No ophthalmology consult placed. ED physician documents "AMD" in the past medical history. No laterality, no stage, no AMD-specific documentation.

**ICD-10-CM (AMD as additional diagnosis):**
- **[[H35.3190]]** — Nonexudative AMD, unspecified eye, stage unspecified *(appropriate — no exam, no records, laterality genuinely unknown)*

> [!tip] ED Is One of the Few Truly Defensible H35.3190 Settings
> The ED physician does not perform a slit-lamp exam or obtain OCT. They cannot specify eye or stage from the available information. **[[H35.3190]]** is the correct code here — and it's appropriate to document it as an additional diagnosis to capture the vision-related fall risk in the case record.

---

### Scenario 2 — PCP Referral Note Only, No Prior Records (Outpatient New Patient)

> **Clinical Vignette:** A new ophthalmology patient presents with a referral from their PCP that says only "AMD — please evaluate." The physician's note today is the first exam. OCT is performed and shows bilateral intermediate dry AMD. The physician documents: "Nonexudative AMD, bilateral, intermediate stage — large drusen OU — initiate AREDS2."

**ICD-10-CM:**
- **Do NOT use [[H35.3190]]** for this encounter
- ✅ Use [[H35.3132]] — Nonexudative AMD, bilateral, intermediate dry stage
- The physician's note TODAY established the laterality (bilateral) and stage (intermediate) — code to the full specificity the current encounter supports

> [!important] H35.3190 Is for the Referral Note — Not the Evaluation Encounter
> The PCP's referral note would legitimately use only "AMD" without specificity — that's **[[H35.3190]]** territory in the PCP's hands. But the **ophthalmologist's evaluation note** on the same day creates complete documentation (bilateral, intermediate) — at that point, [[H35.3132]] is the correct code for the ophthalmology claim. Never carry the referral note's low-specificity code to the ophthalmology encounter when the ophthalmologist documented the full clinical picture.

---

### Scenario 3 — Inpatient, PCP Admission, AMD in Problem List Only (Inpatient)

> **Clinical Vignette:** A 74-year-old male admitted by hospitalist for sepsis. Problem list from prior admission includes "AMD." No ophthalmology records available. No consult placed. CDI query to hospitalist: "Cannot specify — not my area." AMD meets **UHDDS** criteria (documented active condition).

**Additional Diagnosis:**
- **[[H35.3190]]** — Nonexudative AMD, unspecified eye, stage unspecified *(acceptable after query — inpatient coder cannot access outpatient ophthalmology records within coding window)*

> [!note] Document the Query in the Coding Workflow
> Even when **[[H35.3190]]** is the final code, document that a query was sent and the outcome was "clinician unable to specify." This protects coding compliance in the event of an audit and demonstrates due diligence.

---

### Scenario 4 — Pattern Alert: H35.3190 Appearing on Retina Claims (Audit Scenario)

> **Clinical Scenario:** During an internal coding audit, a compliance team finds that 22 outpatient retina encounters from a single physician over 6 months were coded as **[[H35.3190]]**. All encounters include OCT reports labeled **OD (right eye)** or **OS (left eye)** and contain language like "medium drusen" or "large drusen with pigment changes."

**Findings and Correct Action:**
1. **All 22 encounters are under-coded** — OCT reports establish both laterality and stage
2. **Retrospective correction needed** — claims within the correction window should be amended
3. **Review the physician note template** — the assessment/plan section likely does not include eye-specific AMD stage language; template should be updated to prompt "AMD: Right/Left/Bilateral, Stage: _____"
4. **Provider education** — physician may be dictating "**AMD**" without stage because prior template did not prompt specificity
5. **Compliance documentation** — findings, corrections, and education documented in compliance file

> [!danger] Pattern of H35.3190 on Retina Claims = Audit Trigger
> CMS and commercial RACs can identify patterns of unspecified laterality codes in specialty-specific contexts. A retina practice with recurring **[[H35.3190]]** claims is an anomaly that invites scrutiny — retina visits always include OCT with eye-specific results. Investigate the root cause, correct prospectively, and document the corrective action.

## ⚠️ Coding Pitfalls and Tips

| | Pitfall or Tip |
|---|---|
| ❌ | **Never use [[H35.3190]] in a retina practice outpatient setting** — the eye is always documented in an ophthalmology exam; laterality unspecified is not credible [web:183] |
| ❌ | **Never use [[H35.3190]] when an OCT report is attached** — OCT is labeled OD/OS/OU; read it and assign the specific code |
| ❌ | **Never default to [[H35.3190]] because it's "safe"** — it's the opposite of safe; it's a compliance liability and a payer rejection risk |
| ❌ | **Never use [[H35.3190]] when prior notes document which eye** — prior documentation establishes laterality even if today's note is vague |
| ❌ | **Never skip H35.319x in favor of bilateral code when only one eye is affected** — if right eye only → H35.311x; do not code "bilateral" to avoid the laterality question |
| ✅ | **H35.3190 IS appropriate** for ED, PCP, and inpatient contexts where eye was never examined and records are unavailable [web:77] |
| ✅ | **When stage IS known but eye IS NOT** → use H35.3191-H35.3194 (partial fix — better than H35.3190) |
| ✅ | **When eye IS known but stage IS NOT** → use H35.3110/H35.3120/H35.3130 (partial fix — better than H35.3190) |
| ✅ | **Use the double CDI query template** above when both elements are missing — two-dimensional query resolves both deficiencies at once |
| ✅ | **A pattern of H35.3190 on specialty claims** → escalate to compliance; investigate template, coder workflow, and provider documentation habits |
| ✅ | **Right-eye single-deficiency equivalent**: [[H35.3110]]; **left-eye**: [[H35.3120]]; **bilateral**: [[H35.3130]] |
